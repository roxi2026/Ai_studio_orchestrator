## 2026-08-06 - O(1) Incremental Rendering & Selective Network Interception
**Learning:** In browser extension UIs that continuously update live logs, using innerHTML to re-render the entire logs array at O(N) complexity causes huge layout reflows and memory thrashing, especially during high-throughput orchestration cycles. Transitioning to a monotonic state tracking variable (totalLogs) and O(1) DocumentFragment batch appendChild drastically improves performance. Similarly, Main World interception scripts can suffer from high CPU/memory overhead if they clone and parse all network requests (images, CSS, telemetry) indiscriminately.
**Action:** Always maintain a monotonic totalLogs counter, use DocumentFragment for batch DOM rendering, and filter intercepted network requests as early as possible before cloning response bodies.
