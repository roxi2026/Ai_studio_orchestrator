## 2026-07-25 - Telemetry UI Rendering & Network Interception Bottlenecks
**Learning:** Wiping and re-rendering log list containers using `innerHTML` with string-based map/join operations creates a major O(N) rendering bottleneck and causes a timestamp drifting bug where past logs are re-stamped with the current time. Additionally, intercepting every network request in `inject.js` using `.clone().text()` on fetch/XHR responses creates heavy CPU and memory overhead on busy pages.
**Action:** Always implement O(1) incremental rendering via `DocumentFragment` combined with a monotonic counter like `totalLogs` to track sliding windows and preserve static timestamps. Apply early-exit host-based filtering in network interceptors to process and broadcast only the API requests we care about.
