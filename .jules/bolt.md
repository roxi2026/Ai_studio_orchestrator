## 2025-05-18 - Non-reflow DOM extraction vs container text extraction
**Learning:** Using `innerText` on DOM elements forces Blink/V8 synchronous layout reflows (layout thrashing). Replacing `innerText` with `textContent` across DOM extraction operations (like `GET_LINKS`, `EXTRACT_SPATIAL`, `smartAdvance`, `getContext`, `READ_ARTICLE`) avoids layout reflows and speeds up execution significantly (~33x+ speedup). However, for `EXTRACT_TEXT` targeting full containers like `document.body`, `innerText` is required to strip out raw `<script>` and `<style>` tag contents unless script/style tags are explicitly removed from a cloned tree first.
**Action:** Use `textContent` for node-level extractions (`a[href]`, buttons, form elements, article clones) to eliminate forced reflows, but preserve `innerText` (or clone and purge non-renderable nodes) when extracting general container text.
