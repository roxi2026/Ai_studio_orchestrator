## 2026-07-19 - Incremental Log Rendering and Target URL API Filtering

**Learning:** Re-rendering a growing log list with O(N) `innerHTML` on every state update induces severe layout thrashing, style recalculations, and slow UI responsiveness, especially when logs can append frequently. Replacing this with O(1) incremental rendering using `DocumentFragment` and `createTextNode` reduces rendering times and completely eliminates DOM churn. Additionally, unconditionally intercepting all fetch, XHR, and WebSocket requests in the host page main-world `inject.js` generates immense IPC (`postMessage`) overhead, garbage collection pressure, and response body cloning costs. Normalizing URL objects, Request objects, and strings to filter for specific AI Studio API targets (`generateContent`, `v1beta`, `executor`, `reviewer`) minimizes CPU cycles and restricts network injection overhead to only the relevant microservices.

**Action:** Always maintain a monotonic log state counter (like `totalLogs`) in the orchestrator script to track real logs vs. sliding arrays. In UI scripts, track a local rendering bookmark and use incremental append patterns instead of innerHTML maps. For network interceptions, use selective host-based URL filters early before cloning bodies or posting messages across contexts.
